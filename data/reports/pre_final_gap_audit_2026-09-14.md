## 1. Исходное состояние (кратко)

Рабочий демо-MVP: FastAPI + React, синтетика, portable EXE/BAT.

Уже есть и работает:

- ожидаемая валовая маржа = сглаженная P(продажа) × средняя маржа при продаже;
- свежесть истории (экспоненциальный вес);
- сглаживание малых выборок;
- иерархический fallback (6 уровней);
- совместный выбор 70→50 через ILP (PuLP/CBC);
- лимиты менеджеров + общий лимит команды;
- защита от утечки будущих данных (`date < as_of`);
- объяснения, ручной override с проверкой загрузки;
- анализ мощности, симулятор эффекта;
- импорт CSV/Excel;
- ~33 pytest.

## 3. Форма и уверенность — критическая проверка

| Вопрос | Ответ | Где |
| ------ | ----- | --- |
| Где считается форма? | `analytics/form.py` → `compute_manager_form` | 30 vs предыдущие 30 дней, GM на переговор |
| Где считается уверенность? | `analytics/confidence.py` | n и уровень fallback |
| Где отображаются? | Managers, Dashboard, Recommendations | UI |
| Участвуют ли в решении? | **Форма — нет** в objective. **Уверенность — частично** (сортировка приоритета, reject_reason, tie-break greedy) | `pipeline.py`, `optimal.py` |
| Входят ли в objective ILP? | **Нет** — только `expected_gm` | `optimal.py` |
| Входят ли в Expected GM? | Косвенно: свежие сделки уже тяжелее через recency; уверенность влияет на выбор уровня статистики | `scoring.py`, `recency.py` |
| Влияют ли на ranking UI? | Да (priority) | `pipeline.py` |
| Только UI? | Форма — почти только UI/объяснения | `explanation.py` |

### Решение по внедрению `AdjustedValue = ExpectedGM × K_form × K_confidence`

**Не внедрять.** Причины:

1. Свежесть уже меняет P(sale) и GM → дополнительный K_form = двойной учёт формы.
2. Малая выборка уже сглаживается и уходит в fallback → дополнительный K_confidence = двойной учёт.
3. ILP уже оптимален по Expected GM; смена objective меняет 70→50 без бизнес-необходимости.
4. Аудит требует честности сильнее, чем «красивого» множителя.

## 5. Что менять / не менять

### Менять (точечно)

1. Форма: short 14 / long ~180 + порог просадки в настройках и в метрике формы (без ILP).
2. Half-life свежести: понятная настройка (связь с λ).
3. UI: чётко развести «ожидаемая валовая маржа» и «приоритет»; добрать карточку.
4. Документы: **один** главный ответ 2–4 стр. + 3 коротких PDF; упростить README.
5. GitHub readiness: `.gitignore`, без секретов; **не** публиковать без подтверждения.
6. Hosting: рекомендация без ломания архитектуры.
7. Новый FINAL ZIP + чистый smoke + финальный отчёт.

### Не менять

- ILP / caps / 70→50;
- формулу Expected GM;
- smoothing / fallback;
- leakage filter;
- manual override capacity;
- стек и «тяжёлую» ML.
