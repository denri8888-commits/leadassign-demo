# Сценарий демонстрации (5–10 минут)

## Подготовка

1. Запустить backend на `:8000` и frontend на `:5173`.
2. Открыть главную: «Распределение заявок».
3. При необходимости нажать «Сгенерировать новый день» (seed `42`, сценарий «Нормальный день»).

---

## Сценарий

1. **Dashboard** — показать KPI: 70 заявок → 50 рекомендовано → 20 в очереди, ожидаемая GM и прирост к ручному baseline.  
   Фраза: «Система не ищет лучшего менеджера вообще — она ищет лучшее назначение заявки менеджеру при лимите переговоров».

2. **График сравнения подходов** — случайный / ручной / жадный / оптимальный. Объяснить, почему правило «каждой заявке лучший» бьётся о capacity.

3. **Рекомендации** — открыть таблицу всех 70. Отфильтровать «Не обрабатывать» и показать причины.

4. **Карточка заявки** — клик по строке: рекомендованный менеджер, «Почему он», альтернативы.

5. **Как получилась цифра** — вероятность, чек, GM%, сглаживание, свежесть → ожидаемая GM.

6. **Малая выборка** — сценарий `small_sample_hot` или заявка с низкой уверенностью: «2 из 2 ещё не доказательство преимущества».

7. **Текущая форма** — раздел «Менеджеры» или график формы; сценарий `form_drop` для Менеджера 4.

8. **Перегруз** — сценарий `star_overloaded`: сильный менеджер с малой capacity не забирает все заявки.

9. **Capacity** — экран аналитики 50→70, diminishing returns, осторожная формулировка про найм.

10. **Результат дня** — финальный презентационный экран с оговоркой про демо-данные.

11. **Что дальше** — «Допущения и развитие»: этап 2 признаки, этап 3 ML, CRM, без пола/возраста как прямого критерия.

---

## Ключевые фразы

- «Бизнес-цель — ожидаемая валовая маржа при ограниченной мощности, а не обработка всех заявок».
- «70→50 решается одновременно с назначением менеджера».
- «На демо-данных видим потенциальный эффект; на реальных данных нужен A/B».
